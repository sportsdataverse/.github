# CFB — sport-specific reference

`methods.md` says "not covered" for CFB rating engines, EP/WP/CP/xYAC, and simulation — this file is where those mechanisms live. Shorthand: `plan.md` = `ClaudeCowork/plans/2026-07-07-cfb-ratings-prediction.md`, `design.md` = `.../specs/2026-07-07-cfb-ratings-prediction-design.md`, `higher-order.md` = `.../notes/2026-08-03-cfb-higher-order-models.md`. Code facts are file:line, grepped directly.

## 1. Two layers, two mechanisms

**Layer 1 (bundled XGBoost, `cfb/models/*.ubj`)**: `ep_model`, `wp_spread`, `wp_naive`, `cfb_cp_model`, `qbr_model`, `fg_model`, `fd_model`, `two_pt_model`, `xpass_model` + `punt_distribution.parquet`, applied **inline inside `CFBPlayProcess`** — CFB has no standalone `ep_wp.py`; the six score-time boosters load at module scope (`cfb_pbp.py:139-165`). `*.card.json` (7/9 boosters have one; `fd_model.ubj`/`cfb_cp_model.ubj` ship with **no card**) all read `training_seasons: [2004, 2025]`, `trained_date: "2026-08-02"` — this **supersedes** `data-sources.md` §1c's audit-sourced claim that "`training_seasons: null` on every model card is prose-only provenance," which was true only pre-0.0.75-retrain. Era one-hots (`era0..era3`) cut **2006/2013/2020** (`FD_ERA_BOUNDS`, `cfb_fourth_down.py:94`; used by `fg`/`fd`/`two_pt`/`qbr`). **Layer 2 (closed-form, no bundled artifact, the T2.1 spine, `plan.md`/`design.md`)**: `cfb_ratings` → `cfb_game_predict` → `cfb_resume`/`cfb_season_odds`; the only fitted numbers (HFA, σ, points-scale) are module constants in `cfb_prediction_constants.py`, overwritten by a committed `dev/cfb_prediction/fit_pregame.py` — this layer never touches EP/WP.

## 2. Mechanism (the gap `methods.md` leaves)

**Ratings, two independent solvers.** `cfb_ratings.efficiency_ratings` fits a **ridge** (`_fit_opponent_ridge`, reused from `cfb_adjusted_epa`) on competitive plays, then **nets** each team's raw per-game EPA against the fitted opponent strength (`cfb_ratings.py:267-283`) — not coefficient+intercept, which runs ~1.8x hot (max ~0.63 vs the netted ~0.35; releases before 2026-07-28 shipped the hot scale). `cfb_opponent_adjust.opponent_adjust` is a separate **iterative fixed-point** solver ("KenPom/GameOnPaper-style… iterated to convergence," `cfb_opponent_adjust.py:297-299`), league-agnostic, feeding the FEI/tempo/field-position family. **EP/WP/CP/QBR/decision recipe** mirrors NFL's shape (7-class EP softprob; spread+naive WP) but is inlined per-play rather than factored into a standalone module; FG/FD/2pt/xpass are independent boosters read at decision points, not derived from EP/WP. **Simulation** — `make_ratings_compute_results` samples `round(Normal(exp_margin, margin_sd))` in **points** (`cfb_season_odds.py:52,100-116`), injected as a `compute_results` closure into the shipped nflseedR-ported `cfb_simulations` engine (season/standings/bracket machinery reused verbatim) — its non-FBS-population bug is failure-modes.md row 11. **The pregame trio isn't a flat constant** — `slope_by_games` (not `net_points_scale`, a separate fallback scalar) is fit per games-played bucket, shipped `{"0-3": 10.6201, "4-5": 26.0576, "6-7": 42.0032, "8-20": 54.4874}` (`cfb_prediction_constants.py:122-129`, repeated `:178-183`; `cfb_season_odds.py:99` dispatches `ns = slope_for_games(...) if c.slope_by_games else c.net_points_scale`) because the attenuation curve (13.69 MAE, measured pre-refit at 10.8→55.4 in `higher-order.md:171-172`) beats a flat-slope refit (14.27 MAE): early-season ratings are noisier and get shrunk toward a smaller points-scale than a fully-played season.

## 3. Data — cross-reference `data-sources.md`'s CFB loader table + §1b/§1c

`load_cfb_pbp` feeds both layers directly. The as-of team-week spine (`cfb_ratings_weekly` + `cfb_team_summaries_weekly`) feeds `higher-order.md`'s Phase-2/3 GBM — but the two datasets publish colliding `adj_off_epa`/`adj_def_epa` column names that correlate only 0.64-0.68 with each other (`cfb_team_summaries_weekly` is FBS-vs-FBS kneel-filtered; `cfb_ratings` is garbage-time-filtered and includes special teams), and the divergence is undocumented (`higher-order.md` §4b "Open items"). Recruiting-family floors (2002/2005/2005) live in `data-sources.md` §1b, not repeated here.

## 5. Oracle

ESPN FPI is the primary always-free CFB oracle (`data-sources.md` §4's row; `load_cfb_fpi_weekly` / `espn_cfb_season_powerindex_leaders`); committed SP+/FEI snapshots are the secondary validation targets (`design.md` §4). Gated by `cfb-ratings-oracle.py`'s Spearman floors (`metrics-and-gates.md` §1 and §6) — Spearman alone already missed a 1.8x-hot ridge scale once in this ecosystem, shipping unseen because rescaling doesn't move rank correlation (`metrics-and-gates.md` §6); the fix added a magnitude gate alongside the rank gate, which is exactly why §2 above states the netted-vs-hot-scale distinction explicitly rather than assuming Spearman alone would have caught it.
